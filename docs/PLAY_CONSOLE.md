Play Console に入力する内容と、公開までの流れをまとめたものです（v2.20 時点。8 章は v2.21 で調べ直し）。v2.21 からは内部アプリ共有で使っています（README の「内部アプリ共有で入れる」）。

## 2. プライバシーポリシーの URL

**https://github.com/namdalou/HighwayModeAPP/blob/main/docs/PRIVACY.md**

- Play Console の「アプリのコンテンツ」→「プライバシー ポリシー」に、この URL を入れます（リポジトリは公開なので、誰でも開けます）。
- アプリの設定画面の「プライバシーポリシー」も、この URL を開きます。
- 見た目を整えたいときは、GitHub Pages で公開できます（任意）:
  1. GitHub のリポジトリの Settings → Pages →「Build and deployment」の Source を「Deploy from a branch」、Branch を `main`・フォルダを `/docs` にして Save
  2. 数分後に `https://namdalou.github.io/HighwayModeAPP/PRIVACY.html` で開けるようになります
  3. リポジトリの Settings → Secrets and variables → Actions → Variables に `PRIVACY_URL`（値は上の URL）を作ってから build-app を実行すると、アプリの中のリンクもその URL になります。Play Console の URL も同じものに変えます

## 3. データ セーフティ（「アプリのコンテンツ」→「データ セーフティ」）

### このアプリが端末の外へ送る情報（調べた結果）

| 送り先 | 送るもの | いつ |
|---|---|---|
| GitHub | なし（地図データをダウンロードするだけ） | 地図データの更新のとき |
| 公開の Overpass API のサーバー（OpenStreetMap の地図データ） | 現在地の周りの地図の区画（おおよその位置） | アプリに同梱した地図データに無い範囲を走るときだけ（日本の高速道路は同梱しているので、まれ） |
| TomTom / HERE / Google（渋滞情報） | 前方の道路の位置（座標）と、利用者が自分で入れた API キー | 利用者が渋滞情報を設定したときだけ（高速道路を走行中） |
| Google Play | （Google Play が処理。開発者は受け取らない） | アプリ内アップデート・レビュー |

音の解析・曲の情報・通知の内容（ナビの案内）・設定は、端末の中だけで使います。広告・解析・クラッシュ報告の仕組みは入っていません。

### 回答（おすすめ）

| 質問 | 回答 | 理由 |
|---|---|---|
| 必須のユーザー データの種類を収集または共有しますか | **はい** | 上の表のとおり、位置情報を地図・渋滞情報の取得のために送るため |
| ユーザー データはすべて転送時に暗号化されていますか | **はい** | どの通信も HTTPS |
| アプリでアカウントを作成できますか | **いいえ** | アカウントは無い |
| ユーザーがデータの削除をリクエストする方法を提供していますか | **いいえ** | 開発者はデータを受け取らず、保存もしていないため（端末内のデータは、アプリの削除・アプリのデータの削除で消える） |

データの種類は「位置情報」の 2 つだけを選びます。

| データの種類 | 収集 | 共有 | 一時的に処理 | 必須 / 任意 | 目的 |
|---|---|---|---|---|---|
| おおよその位置情報 | はい | いいえ | はい | 必須（利用者は選べない） | アプリの機能 |
| 正確な位置情報 | はい | いいえ | はい | 任意（渋滞情報を設定したときだけ） | アプリの機能 |

- **一時的に処理**：アプリは送った位置をどこにも保存せず、地図・渋滞の情報を受け取るためだけに使うので「はい」。
- **共有は「いいえ」にした理由**：送り先は、アプリの求めに応じて地図・渋滞の情報を返すサービス（Google の説明の「サービス プロバイダ」にあたる）として使っていて、渋滞情報は利用者が自分で提供元と API キーを選んで使う機能のため。判断に迷う場合は、「共有」を「はい」（目的: アプリの機能）にしても差し支えありません。
- ほかのデータの種類（個人情報・写真・音声・メッセージ・アプリのアクティビティ・端末の ID・クラッシュログなど）は**選びません**（端末の外へ送らない・集めていない）。
- 設定の「不具合を報告する」（v2.22）は、落ちたときの記録などを画面に出し、利用者が共有の画面で選んだアプリ（メールなど）で送るもので、アプリが自分で送ることはありません。そのため「クラッシュログ」も選ばなくてよいと考えています（迷う場合は「クラッシュログ: 収集する・任意・アプリの機能（不具合の修正）」を選んでも差し支えありません）。

## 4. 権限・常駐サービスの申告

### フォアグラウンド サービス（「アプリのコンテンツ」→「フォアグラウンド サービスの権限」）

Android 14 以降を対象にしたアプリは、使っている常駐サービスの種類ごとに、説明と、動きを見せる動画（YouTube の限定公開などの URL）が必要です。このアプリは 2 種類を使います。

**位置情報（location）** — 機能の説明の例:

> 高速道路を走行中に、前方の IC・JCT・SA/PA までの距離と到着予定時刻、オービスの接近を表示・音声で知らせるため、利用者がアプリ（スマホ、または Android Auto の車の画面）を開くと常駐サービスを始め、画面を消している間や Android Auto の画面だけで使っている間も位置情報を受け取ります。常駐中は通知を表示し、通知の［停止］・設定の［終了］で止められます。Android Auto との接続が切れたあとは約 3 分で自動で止まります。

**データ同期（dataSync）** — 機能の説明の例:

> 利用者が設定画面の「最新の地図データに更新」を押したとき、全国の地図データ（数 MB〜十数 MB）を画面を消しても途中で止まらないようにダウンロードします（進み具合を通知に表示し、［中止］で止められます）。また、Android Auto の車の画面だけで使っていて位置情報の常駐ができないときに、地図データと渋滞情報の取得を続けます。

**動画の撮り方**：スマホの画面録画で、①アプリを開く → ②通知に「ハイウェイモード」の常駐が出る → ③画面を消しても通知が更新される（高速道路を走るか、開発者向け設定の「デモ走行」）、④設定 →「最新の地図データに更新」で通知に進み具合が出る、を撮ります。

### そのほかの権限

| 権限 | 申告 | メモ |
|---|---|---|
| 位置情報（正確な位置） | 不要 | バックグラウンドの位置情報の権限（ACCESS_BACKGROUND_LOCATION）は使っていないので、その申告はいりません |
| マイク（RECORD_AUDIO） | 不要 | スペクトラムアナライザーの解析に Android が求める権限。最初の説明で「録音しない」と伝えています |
| 通知へのアクセス | 不要 | 曲名とナビの案内を読むため。最初の説明で伝えています |
| DUMP | 不要 | 利用者が Shizuku で許可したときだけ使う任意の権限 |

>
> ■ ハイウェイモード

## 7. テストと公開の流れ

0. **最初に**（v2.22 で追記）：アプリを作っただけの状態は「未公開のアプリ」で、内部テストは使えるが、**内部アプリ共有は使えない**（「アプリを公開する必要があります」と出る）。ダッシュボードの「アプリのセットアップ」（この手引きの 2〜6 章・「ログインの詳細」・常駐サービスの申告・ストアの設定）をすべて済ませ、リリースを作って「公開の概要」→「変更を審査に送信」する。審査が通ると「未公開のアプリ」でなくなり、内部アプリ共有が使えるようになる
   - 常駐サービスの申告は、データの同期 →「ネットワーク処理: その他」、位置情報 →「バックグラウンドでの位置情報の更新: ナビ」。説明の文は 4 章、動画は画面録画を YouTube の限定公開で
   - ストアの設定：カテゴリ「地図、ナビ」、連絡先のメールアドレス（必須）、外部マーケティングはオフ
1. **内部テスト**（審査なし・テスター 100 人まで）
2. **クローズド テスト**（v2.22 で使い始めた。版は内部テストと同じ鍵で署名されるので、内部テストの版の上から更新できる。Android Auto の品質の指摘はメールで届くが配布は止まらない）：**2023 年 11 月 13 日以降に作った個人のデベロッパー アカウントは、製品版を公開する前に、12 人以上のテスターが 14 日間続けて参加したクローズド テストが必要**です（組織のアカウントは不要）。テスターは Google グループかメール アドレスで追加し、テスト用のリンクから参加してもらいます。14 日たったら「製品版へのアクセスを申請」します（審査は通常 7 日以内）。
3. **製品版**：AAB を上げて審査に出します（記事では、いまは数時間〜1 日ほどで公開されることが多いとのこと）。

## 8. Android Auto の審査について（重要。v2.21 で調べ直し）

### 審査が配布を止めるかどうか（配布のしかたごと）

Android Auto に対応した AAB・APK を上げると、[Android for Cars の品質の決まり](https://developer.android.com/docs/quality-guidelines/car-app-quality)で審査されます（[Distribute to cars](https://developer.android.com/training/cars/distribute)）。

| 配布のしかた | Android Auto の審査 |
|---|---|
| 内部アプリ共有 | なし |
| 内部テスト | なし |
| クローズド テスト | あり。決まりに合わないと指摘のメールが届くが、配布は止まらない |
| オープン テスト・製品版 | あり。決まりに合わないと公開されない（取り下げるまで、スマホ向けの更新も止まる） |

### このアプリが合わない決まり

このアプリは「ナビ」の分類で、ナビ用の画面（NavigationTemplate）の地図の面に、音楽の画面・スペアナ・ハイウェイモードを自分で描いています。決まりのうち、次のものに合いません。

| 決まり | 内容 | このアプリ |
|---|---|---|
| NF-1 | ナビの分類のアプリは、自分でターンバイターンの道案内をする | 無い（ナビアプリの案内を写して出すだけ。ほかのアプリが案内していないと何も出ない） |
| NF-2 | 地図の面には地図だけを描く。案内の文・到着予定は決まった部品に出す（制限速度などの補助の情報は地図の上に描いてよい） | 音楽の画面・スペアナ・施設の一覧を描いている。地図が無い |
| SA-1 | 動く絵（アニメーション）を出さない。停車中も、運転に関係のないものは不可 | スペアナ |
| ST-1 | 文字を自動で流さない | 曲名の流し表示 |
| PC-1 | 車向けの種類の外の機能を入れない | 音楽を操作する画面（指摘される可能性が高い） |
| NF-3・NF-4・NF-6・NF-7・VC-1 | 案内の通知・メーターの中の表示・ほかのアプリや音声（Gemini・Google アシスタント）からの「○○へ案内」を受け付ける・審査用のテスト走行 | 無い |

SA-1・ST-1 は、運転中に使う分類（ナビ・地点（POI）・音楽・天気・IoT など）すべてに当てはまります。停車中だけの分類（ゲームなど）は、走り出すと画面を出せません。そのため、**車の画面にスペアナを出したまま製品版の審査を通す方法はありません**。

### 決めたこと（v2.21）

**内部アプリ共有で使う**（審査なし。手順は README の「内部アプリ共有で入れる」）。あわせて:

- 内部アプリ共有の版は、Google が内部アプリ共有用の鍵で署名し直します。内部テスト・APK の版とは上書きし合えないので、切り替えるときは設定を書き出してから入れ直します。
- アプリ内アップデート・レビュー（v2.20）は、内部アプリ共有では働かないので既定で止めました。

### あとで公開を考えるときの案

1. スマホのアプリとして製品版で公開し、Android Auto は内部アプリ共有・内部テストで使い続ける（製品版の AAB から Android Auto の部分を外すビルドを用意する）。
2. 製品版の車の画面だけを「前方の SA・PA・IC を探すアプリ」（地点（POI）の分類。道案内は要らない）にする。Android Auto が描く地図と施設の一覧で、スペアナは出せない。
3. ナビの分類のまま、決まりに合わせて作り込む（自分の道案内・地図・案内の通知など。とても大きな作業で、それでもスペアナは出せない）。

- 日本の外の担当者が審査するので、ナビ・地点のアプリは、位置を変えるアプリ（モックの位置）で動く必要があります（このアプリは動きます）。審査用の説明は英語で書きます。

## 9. 参考にした記事の項目のうち、入れなかったもの

| 項目 | 入れなかった理由 |
|---|---|
| Firebase Analytics / Crashlytics | 利用状況とクラッシュの情報を開発者（Google）へ送ることになり、「端末の外へ送らない・解析ツールを入れない」というこのアプリのプライバシーの方針と、データ セーフティの回答が変わるため。クラッシュは Play Console の「Android Vitals」で見られます（対応表は AAB に入っているので、元の名前で読めます）。入れる場合は、Firebase のプロジェクト（google-services.json）を作る必要があります |
| AdMob・同意管理（UMP） | 広告を出さないため |
| アプリ内課金・定期購入 | 有料の機能が無いため |
